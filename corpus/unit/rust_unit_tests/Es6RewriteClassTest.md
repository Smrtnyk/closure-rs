## Es6RewriteClassTest (post-call assertions, gate 0.2 (a))

Methods of `com.google.javascript.jscomp.Es6RewriteClassTest` whose assertions after the hooked `test(...)` call inspect Java-internal objects of the output AST (`getLastCompiler().getJsRoot()`):
- category `color`: the `Color` objects that ConvertTypesToColors and the multistage TypedAST round trip attach to nodes (identity, `getPrototypes()`, `getInstanceColors()`, `StandardColors` constants);
- category `node-identity`: source positions of Java `Node` objects, compared with `assertNode(..).hasEqualSourceInfoTo(..)` against a separately parsed input AST (helper `testAndReturnAsts`, Es6RewriteClassTest.java:3460-3466; lengths are zeroed on the input side because multistage compilation does not keep them).

The AST comparison ignores both. The records carry no `postCall.pass.*` key; their `postCall.compiler` keys (`externProperties`, `accessorSummary`, `typeMismatchesError`) hold neither colors nor node positions, `testFieldsAfter` is empty and no postcondition runs. The records still replay (input, expected output, diagnostics) but are excluded from gate (a) counting; the checks below are ported as Rust unit tests next to Es6RewriteClass.

- Es6RewriteClassTest#testSimpleClassStatement: `class C { }` becomes `let C = function() {}`; the NAME `C` has a constructor color and the FUNCTION node has the same color as `C` (Es6RewriteClassTest.java:84-96)
- Es6RewriteClassTest#testClassStatementWithConstructor: `class C { constructor() {} }` becomes `let C = function() {}`; the NAME `C` has a constructor color and the FUNCTION node has the same color as `C` (Es6RewriteClassTest.java:99-111)
