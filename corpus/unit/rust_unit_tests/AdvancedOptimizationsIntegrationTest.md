## AdvancedOptimizationsIntegrationTest: post-call assertions ported as Rust tests (gate 0.2 (a), D-015)

Test class com.google.javascript.jscomp.integration.AdvancedOptimizationsIntegrationTest (reference commit bb8c8e7). These methods assert after a hooked IntegrationTestCase call. Integration records carry no post-call snapshot (`postCall`), integration `compile` records are always notCaptured, and corpus/unit/postcall/ accepts no `observed.*` or `outcome` claim. So each method is ported as a Rust integration test that runs the same compile and makes the same assertions. Each line names what that test checks. The reasons, including which parts the replay's `observed`/`outcome` comparison already covers, are in corpus/unit/postcall/AdvancedOptimizationsIntegrationTest.json.

- AdvancedOptimizationsIntegrationTest#testAngularPropertyNameRestrictions: with angularPass and ADVANCED, 250 `window.fooN=true` assignments compile without diagnostics and no renamed property starts with an Angular-reserved first character
- AdvancedOptimizationsIntegrationTest#testSourceInfoForReferenceToImportedSymbol: after ADVANCED renaming across goog.modules, the reference to the imported foo (now `a`) keeps the usage script's source name, line 3 and charno 4
- AdvancedOptimizationsIntegrationTest#testRequireAndEncourageInlining_complexCase: with ADVANCED and the inlining options, a @requireInlining function whose `.name` is read makes the fourth compile throw a RuntimeException ('Validity check failed for earlyInlineVariables') whose cause is an IllegalStateException whose own cause's message contains '@requireInlining node failed to be inlined'
