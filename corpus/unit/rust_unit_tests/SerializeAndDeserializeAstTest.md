## SerializeAndDeserializeAstTest (post-call assertions, gate 0.2 (a))

Test class `com.google.javascript.jscomp.serialization.SerializeAndDeserializeAstTest` (reference commit bb8c8e7). Every record is the hooked `test`/`testNoWarning` call inside `toInputStream` or `runWithoutExpected`, which serializes the AST through `SerializeTypedAstPass` into the `consumer` lambda. The test's real check comes after that call, in `run(...)` and `testAndReturnResult`. They deserialize the TypedAst with `TypedAstDeserializer.deserializeFullAst` into a second `Compiler` that the test creates, then assert on what the deserializer rebuilt: script feature sets (`Node.FEATURE_SET`) must match, `AstValidator` must accept the rebuilt tree, and in `testAndReturnResult` the tree must equal the expected code, including JSDoc unless `checkJsDocEquality` is off. Some methods then assert on rebuilt nodes, Colors, `SourceFile` objects, the second compiler's source-map registry, or a `DeserializedAst` field.

Replay compares the serialized TypedAst in every record (`testFieldsAfter.consumer`, in the neutral protobuf encoding of D-017 item 2), so the serializer side is checked by the corpus and the records stay counted, except records 5, 6 and 58, whose on-disk input files the record's inputs do not encode. The deserialized tree is not in any record. Port these checks as Rust unit tests next to the TypedAst deserializer: serialize, deserialize into a fresh compiler, then run the checks below.
