## Resolution

- status: fixed in [#3](https://github.com/Smrtnyk/closure-rs/pull/3) (`OptimizeCalls.ReferenceMap`: `isCallTarget`/`isOptChainCallTarget` read the
  grandparent only after the parent check).
- root cause: `OptimizeCalls.ReferenceMap#isCallTarget` (and `#isOptChainCallTarget`) in Java read
  `parent.getParent()` into a local but dereference it only after `parent.isGetProp()` holds, so a
  reference whose parent is detached (here a constructor reference inlined away by an earlier
  optimization in the same OptimizeCalls run) answers false. The port called
  `get_parent(..).unwrap()` eagerly and panicked (`optimize_calls.rs:473`, exit 101).
- fix: `crates/jscomp/src/optimize_calls.rs`, the grandparent is unwrapped only after the parent
  check, as in Java.
- regression test: `crates/cli/tests/data/fuzz_regressions/optimize-calls-detached-call-target/`
  (ADVANCED; `const d0 = 0; function C(){} C.prototype.val = function(){ return new d0(); };
  console.log(new C().val(), new C().val());`), run by `crates/cli/tests/fuzz_regression_test.rs`.
- same root cause: further exit 0 vs 101 findings of seed 2001 under chunks2, chunks3 and
  advanced; their minimized and original programs all match Java after the fix.
