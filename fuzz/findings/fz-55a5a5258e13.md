## Resolution

- status: fixed by the commit that adds this section.
- root cause: Java's `System.err` is a `PrintStream` whose UTF-8 `OutputStreamWriter` encodes
  with `CodingErrorAction.REPLACE`, so each unpaired surrogate is written as the encoder's
  replacement `?`. The port's type strings were Rust `String`s: `TypeStringBuilder` took the
  record's property names through `JsString::to_string_lossy`, which gives U+FFFD (`EF BF BD`).
  The lossy conversion also changed the order of union members (sorted by their type strings) and
  could make `TypeValidator#formatFoundRequired` see two different types as equal.
- fix: `TypeStringBuilder` holds UTF-16 code units, as Java's `StringBuilder` does, and appends
  property and reference names unchanged; union members sort by those units.
  `JSType#to_string_utf16` / `#to_annotation_string_utf16` return the Java string, and
  `to_string` / `to_annotation_string` the text Java's UTF-8 stream writes
  (`charset::utf8_encoded_text`). `formatFoundRequired` and the property comparator compare the
  UTF-16 strings.
- the same bug at other sites: the diagnostic arguments that were converted into a variable before
  the report call (the known limit of fz-6fc868fd3e39), for example
  `JSC_CONFLICTING_GETTER_SETTER_TYPE`, the corrected list of `JSC_REQUIRES_NOT_SORTED`, the
  duplicate key of `JSC_INVALID_ORDINAL_MAPPING` and the type name of
  `JSC_MISSING_NULLABILITY_MODIFIER_JSDOC`, and the source name of a `--json_streams` input whose
  path holds an unpaired surrogate (diagnostics, manifest, chunk dependencies). That source name
  stays a Rust string, so its source map entry and its identity still differ from Java
  (crates/DESIGN.md, "Source names that hold unpaired surrogates").
- regression tests: `crates/cli/tests/data/fuzz_regressions/record-key-lone-surrogate/`,
  `type-string-lone-surrogate/`, `type-string-lone-surrogate-json/`,
  `diagnostic-args-lone-surrogate/`, `lint-requires-lone-surrogate/` and
  `json-streams-lone-surrogate/`, run by `crates/cli/tests/fuzz_regression_test.rs`.
